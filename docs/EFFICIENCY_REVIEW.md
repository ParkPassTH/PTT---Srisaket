# ตรวจความซ้ำซ้อนและการลดงานเกษตรกร

อัปเดต: 18 ตุลาคม 2569

## สิ่งที่แก้แล้ว

| ปัญหาเดิม | ผลกระทบ | การทำงานใหม่ |
|---|---|---|
| เสียงตอบข้อมูลเพิ่มสร้างรายการใหม่ | Dashboard มีหลายแถวสำหรับเรื่องเดียว | ถ้ามีรายการ `AWAITING_FARMER` ระบบเติมเสียงถัดไปใน `activity_id` เดิม |
| ต้องพูดเลขรายการซ้ำ | ยาวและผิดง่าย โดยเฉพาะผู้สูงอายุ | ระบบผูกจากบัญชี LINE และเลือกรายการค้างล่าสุดอัตโนมัติ |
| AI ส่ง “แปลง 1” แต่ทะเบียนชื่อ “แปลงหนึ่ง” | แจ้งว่าไม่พบแปลงทั้งที่มีจริง | ทำชื่อให้เป็นรูปมาตรฐานแล้วเทียบรหัส ชื่อ และข้อความถอดเสียง |
| มีแปลงเดียวแต่ยังถามชื่อแปลง | ถามข้อมูลที่ระบบอนุมานได้อย่างปลอดภัย | เลือกแปลง active เดียวให้อัตโนมัติ |
| จับแปลงได้แต่ยังแจ้งว่าพืชไม่ครบ | เกษตรกรต้องพูดข้อมูลทะเบียนซ้ำ | เติมพืชจากทะเบียนก่อนประเมิน required fields |
| การอัปเดตรายการเดิมอาจทำให้ตามย้อนหลังยาก | ผู้ตรวจไม่เห็นว่าข้อมูลมาจากเสียงใด | เก็บ source event ทุกครั้งและ snapshot ก่อน/หลังใน AuditEvents |

## กติกาป้องกันการรวมผิดรายการ

- รวมอัตโนมัติเฉพาะรายการของ Farmer ID เดียวกันที่สถานะ `AWAITING_FARMER`
- หากมีหลายรายการค้าง ใช้รายการล่าสุดตามเวลารับข้อมูล
- กิจกรรมที่เสร็จแล้วหรือกำลังตรวจไม่ถูกเขียนทับ
- พืชที่เกษตรกรพูดชัดเจนแต่ไม่ตรงทะเบียนยังถูกส่งให้ ICS ตรวจ ไม่แก้เงียบ ๆ
- รายการซ้ำเก่าจะไม่ถูกรวมอัตโนมัติย้อนหลัง เพราะอาจเป็นคนละกิจกรรมและต้องรักษาหลักฐาน

## งานอัตโนมัติที่ควรทำถัดไป

1. ใช้ Flex Message ให้เกษตรกรกดยืนยัน/แก้ไขได้โดยไม่พิมพ์คำสั่ง
2. เพิ่ม outbox และ worker สำหรับ retry เมื่อ LINE หรือ AI ล่ม โดยไม่ต้องกดเอง
3. เพิ่มเสียงหรือปุ่มเลือกเมื่อมีหลายแปลงชื่อใกล้กัน แทนการให้พิมพ์รหัส
4. เพิ่มรายการกิจกรรมย้อนหลังของตนเองใน LINE เพื่อให้ตรวจได้ก่อนเจ้าหน้าที่
