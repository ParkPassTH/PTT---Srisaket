# แนวทางบันทึกข้อมูลสำหรับเจ้าหน้าที่ ICS

> เอกสารนี้เป็น checklist เบื้องต้นสำหรับการเก็บหลักฐานในระบบ ไม่ใช่การรับรองมาตรฐาน และต้องให้ผู้จัดการ ICS/หน่วยรับรองอนุมัติรายการสาร กฎความเสี่ยง และแบบฟอร์มฉบับใช้งานจริง

## ข้อมูลที่เกษตรกรควรพูดทุกครั้ง

1. วันที่หรือช่วงเวลาที่ทำกิจกรรม เช่น วันนี้ เมื่อเช้า หรือวันที่ 18 ตุลาคม
2. รหัสหรือชื่อแปลงที่ชัดเจน หลีกเลี่ยงคำว่า “ทุกแปลง” หากแต่ละแปลงปลูกต่างชนิด
3. ชื่อพืชที่ทำกิจกรรม
4. กิจกรรม เช่น เตรียมดิน ปลูก ใส่ปัจจัยการผลิต กำจัดวัชพืช เก็บเกี่ยว
5. ชื่อปัจจัยการผลิตและสูตร/แหล่งที่มา ห้ามใช้คำกว้าง เช่น “น้ำยา” หรือ “ยาฉีด”
6. ปริมาณและหน่วย เมื่อใช้ปัจจัยการผลิตหรือเก็บเกี่ยว
7. เหตุผิดปกติ เช่น ปนเปื้อน สารจากแปลงข้างเคียง ผลผลิตปะปน หรือสงสัยว่าผิดมาตรฐาน

ตัวอย่าง: “เช้าวันนี้ แปลง P001 ปลูกหอมแดง ใช้น้ำหมักสูตร 1 จำนวน 20 ลิตร รดทั่วแปลง ไม่พบการปนเปื้อน”

## จุดตรวจเบื้องต้นในระบบ

| จุดตรวจ | ระบบควรทำ | ผู้ตรวจ ICS ต้องยืนยัน |
|---|---|---|
| สมาชิกและแปลง | ตรวจว่าแปลงเป็นของสมาชิกและเปิดใช้งาน | ตัวตน พื้นที่ สถานะรับรอง และสิทธิ์ใช้แปลง |
| พืช | เปรียบเทียบพืชจากเสียงกับทะเบียนแปลง | เป็นการเปลี่ยนพืชจริงหรือเกษตรกรพูดผิด |
| ปัจจัยการผลิต | ตรวจชื่อกับรายการควบคุมที่อนุมัติ | สูตร ส่วนประกอบ แหล่งที่มา และหลักฐานอนุญาต |
| การปนเปื้อน | แจ้งเตือนคำเสี่ยงและเหตุผิดปกติ | แนวกันชน แปลงข้างเคียง การเก็บรักษา และมาตรการแก้ไข |
| ผลผลิต | เก็บพืช แปลง วันที่ ปริมาณ และหน่วย | เปรียบเทียบประมาณการกับผลผลิตจริง |
| ล็อต | เชื่อมกิจกรรมเก็บเกี่ยวกับล็อตเดียว | การแยกเก็บ ปริมาณเข้า-ออก และสถานะเรียกคืน |
| ข้อบกพร่อง | บันทึกเหตุผล สถานะ และผู้ตัดสิน | มาตรการแก้ไข กำหนดเวลา และการติดตามผล |
| หลักฐาน | เก็บ snapshot ก่อน/หลังทุกการเปลี่ยน | ตรวจผู้ดำเนินการ เวลา และเหตุผลย้อนหลัง |

## ข้อมูลทะเบียนที่ยังต้องเพิ่มในระบบ

ตามแนวทาง ICS ทะเบียนสมาชิกควรมีข้อมูลมากกว่าชื่อและรหัส ได้แก่ ที่อยู่ วันที่ขึ้นทะเบียน พื้นที่รวม รายละเอียดแต่ละแปลง ขนาด/GPS/พืช สถานะอินทรีย์หรือปรับเปลี่ยน ประมาณการผลผลิต ประวัติการใช้สาร วันที่ตรวจล่าสุด และเวอร์ชันทะเบียน ปัจจุบันระบบรองรับเพียงข้อมูลแกนหลัก จึงต้องขยาย schema ก่อนใช้ตรวจรับรองเต็มรูปแบบ

## Audit snapshot

ทุก event ต้องมี `entity_type`, `entity_id`, `actor_id`, `action`, `reason`, `before`, `after`, `occurred_at` โดย:

- การสร้างรายการมี `after`
- การแก้ไขหรือเปลี่ยนสถานะมีทั้ง `before` และ `after`
- การล้มเหลวเก็บ snapshot สถานะก่อนและหลังพร้อม error ที่ตัดข้อมูลลับออก
- ไม่ hard delete หลักฐานสำคัญ ให้ใช้ `INACTIVE`, `VOID` หรือ `RECALLED`
- การแก้ Google Sheet ด้วยมืออยู่นอก audit ของแอป จึงควรจำกัดสิทธิ์และใช้ Dashboard เป็นช่องทางแก้ไขหลัก

## เอกสารอ้างอิง

- มกษ. 9000-2564 เกษตรอินทรีย์: การผลิต การแปรรูป การแสดงฉลาก และการจำหน่าย
- คู่มือระบบควบคุมภายในของสำนักงานมาตรฐานเกษตรอินทรีย์ (มกท.): ทะเบียนสมาชิก การตรวจประจำปี การควบคุมเอกสาร การจัดการข้อบกพร่อง การตรวจสอบย้อนกลับ และการเปรียบเทียบประมาณการผลผลิตกับผลผลิตจริง
